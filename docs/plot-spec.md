# Plot spec

The plot spec says **what a plot shows**, never the values. Open-FDD chooses the series and fault strips from the
Haystack model; each app only draws them. One description serves the NF app (ECharts) and any downstream app, so the
same rule or preset shows the same inputs, in the same colours, with the same fault strip.

Two producers build the spec and must emit identical canonical JSON for the same model:

| Producer | Use |
|---|---|
| `open_fdd.plot_spec` (Python, in the `open-fdd` package) | `build_rule_spec(model, rule_id, equip, window, tz=None)`, `build_preset_spec(model, preset_id, equips, window, tz=None)`, `to_json(spec)` |
| `nf-app/static/plot-spec.js` (JS) | `ofddPlotSpec.buildRuleSpec`, `buildPresetSpec`, `toJson` |

The JS side reads its data from `plot-spec-data.js`, generated by `scripts/nf/build_plot_spec_data.py` (CI runs it with
`--check`). The data lives in `open_fdd/data/`: `rcx_presets.json` (the preset registry), `palette.json`,
`units.json` and `plot_spec.schema.json` (JSON Schema, draft 2020-12).

## Selection

Selection uses the model only. A point fills a catalog role (`fdd-catalog.json`) when its NF class is listed for the
role (score 2) or it carries every marker of the role (score 1); weather points fill only `web_*` roles. A rule plot
shows the rule's input roles; a sweep rule (`SV-*`) shows every bound sensor and the sensors its hook assessed. A
preset plot shows the registry's series selectors on every qualifying equip. No point names, name patterns or
role-to-key tables are used. Equips of different sites are never mixed: build one spec per site.

## Fields

| Field | Meaning |
|---|---|
| `spec_version`, `kind` | `1`; `rule` or `preset` |
| `rule_id`, `preset_id` | One of them is set. Old preset ids resolve through `aliases` and come back canonical |
| `site` | `ref`, `tz`, and `tz_source` (`model`, `option`, `sites`, `fallback`) |
| `equip` | `uuid`, `ref`, `dis`, `kind` |
| `window` | `from` and `to`, ISO-8601 UTC |
| `series[]` | `point_uuid`, `equip_uuid` (null for weather), `role`, `dis`, `nav`, `tags`, `class`, `quantity`, `unit_si`, `kind` (`sensor`, `sp`, `cmd`, `status`, `weather`), `axis`, `color_key`, `required` |
| `fault_strips[]` | `rule_id`, `equip_uuid`, `point_uuid`, `sensor_uuid` (set for a per-sensor sweep strip), `source`, `approximate` |
| `missing[]` | `role` and `reason`: `unbound`, `no_data` (a renderer sets it), `unit_unusable` |
| `selection_reason` | One line saying what was bound |

## Rendering it

1. Fetch values for each `series[].point_uuid` over `window`, in SI, from your own store. Decimate on the server
   (min/max buckets, at most about 2000 points per series), keep each series' own timestamps, and break a line where a
   gap exceeds twice the series' median cadence.
2. Draw one trace per series. Group traces on the grid named by `axis`. The legend reads `nav (unit)`; the tooltip adds
   the role, class and tags.
3. Draw one strip per `fault_strips` entry under the signal grids with a linked time axis.

### Stable colours

`color_key` is FNV-1a (32 bit) of the point uuid's UTF-8 bytes, modulo 12. The colour is
`palette.series.<light|dark>[color_key % length]`. It does not change with reloads, windows or apps. Status is never
encoded by line colour: use the strip, plus a dash or marker where a trace needs it. The fixed status colours
(`fault`, `ok`, `unknown`, `stale`) are in `palette.json`.

### Tri-state fault strip

A strip value is 1 (fault), 0 (ok) or null (not assessed). Draw null as a gap, never as ok. `source` says where the
strip comes from: `timeline` is the per-timestamp `fault_timeline` point, `fault_pct` is the rolling result point
(`approximate` is true; draw it dashed), and `intervals` has no point in the model, so the renderer derives the strip
from its own stored fault intervals and draws a gap where it has none.

## Units

The spec names `quantity` and `unit_si`. Data handed to a renderer is always SI. Convert for display only, in the
renderer, with `units.json`: `display.<si|imperial>` gives the unit and `value * mul + add`. A point whose declared unit
is unknown or missing (and is not a Bool or a fraction/boolean role) is left out and listed as `unit_unusable`.

## Presets

`rcx_presets.json` is the canonical registry (ids are Open-FDD's; `aliases` hold older downstream ids such as
`ahu_cooling_valves`). `ahu-cooling-valves` and `ahu-heating-valves` plot the valve command against the supply air
temperature, its setpoint and outdoor air temperature, with the valve fault rules as strips.
